Capítulo 1
Resumen Ejecutivo

Cosmetic Pipeline es una plataforma web B2B desarrollada para digitalizar y centralizar la gestión de pedidos entre distribuidoras y tiendas del sector cosmético. Fue encargada en el marco de la asignatura de Ingeniería de Software de la Universidad Europea de Madrid y desarrollada en 11 semanas por un equipo de 4 ingenieros.

El sistema resuelve un proceso gestionado hasta ahora de forma manual (correo electrónico, teléfono, hojas de cálculo), ofreciendo un portal de compra self-service para las tiendas y un backoffice completo para la distribuidora.

Capítulo 2
Introducción y Contexto

2.1 Descripción del problema

Las distribuidoras de productos cosméticos gestionan sus relaciones comerciales con tiendas minoristas a través de canales informales: llamadas telefónicas, correos electrónicos y catálogos en PDF. Este proceso genera ineficiencias significativas:

  • Pérdida de pedidos por falta de trazabilidad
  • Errores en precios y disponibilidad de stock
  • Gestión manual de incidencias (roturas, productos incorrectos)
  • Ausencia de datos para la toma de decisiones (KPIs, reportes)
  • Dificultad para escalar el número de tiendas clientes

2.2 Objetivos del proyecto

Objetivo principal

Desarrollar una plataforma web B2B que permita a las tiendas realizar pedidos online de forma autónoma y a la distribuidora gestionar todo el proceso desde un backoffice centralizado.

Objetivos específicos

  • Portal de compra self-service para tiendas
  • Gestión del ciclo de vida completo de pedidos
  • Sistema de incidencias posventa
  • Backoffice con KPIs y reportes
  • Integración CSV para importar/exportar datos
  • Autenticación segura con control de acceso RBAC

2.3 Alcance y límites

Dentro del alcanceFuera del alcance
Portal de compra para tiendas (rol STORE)Pasarela de pago real (Stripe, Redsys)
Backoffice para administración y operacionesAplicación móvil nativa
API REST con documentación SwaggerIntegración con ERPs externos

Import/export de catálogo y stock vía CSVFirma electrónica de pedidos

Entorno de demostración: La aplicación incluye datos de demo con 42 productos cosméticos, 2 organizaciones, 4 usuarios de distintos roles y varios pedidos en diferentes estados para facilitar la evaluación del flujo completo.

6.3 Decisiones técnicas destacadas

Gestión de estado

Zustand con middleware persist para la autenticación (tokens en localStorage). TanStack Query para caché de datos del servidor con invalidación automática tras mutaciones.

Cliente HTTP

Wrapper personalizado sobre fetch que inyecta el Bearer token en cada petición y redirige a /login automáticamente al recibir un error 401.

7.3 Gestión de la desviación detectada

En la Semana 9 se identificó que el backoffice acumulaba un retraso de aproximadamente una semana: las páginas de gestión CRUD resultaron ser más complejas de lo estimado (tablas paginadas, diálogos modales, formularios completos).

Decisión adoptada: Se incrementó la dedicación del equipo de frontend durante las semanas 9–10, absorbiendo el retraso sin ampliar la fecha de cierre ni el presupuesto. El margen de contingencia del 10% presupuestado fue suficiente para cubrir el coste adicional.

Gracias a esta medida, el proyecto se entregó completo en el plazo original del 2 de mayo de 2026.

9.2 Lecciones aprendidas en gestión de riesgos

Estimación de páginas CRUD: Las páginas de gestión con tablas, modales, filtros y operaciones CRUD completas requieren aproximadamente el doble de tiempo que una página de solo lectura. En proyectos futuros se deberá aplicar un factor ×2 a estas páginas durante la estimación.

Valor del monorepo: La arquitectura monorepo con Turborepo facilitó la sincronización entre equipos de frontend y backend, evitando problemas de versiones y permitiendo compartir tipos TypeScript entre las dos aplicaciones.

Capítulo 10
Conclusiones y Lecciones Aprendidas

10.1 Consecución de objetivos

El proyecto Cosmetic Pipeline ha alcanzado todos los objetivos definidos en el acta de inicio. Se ha entregado una plataforma B2B completamente funcional que digitaliza el proceso de pedidos entre distribuidoras y tiendas del sector cosmético.

  • Portal de compra self-service con flujo completo (catálogo → carrito → pedido → seguimiento)
  • Backoffice de administración con gestión integral (pedidos, catálogo, usuarios, organizaciones, incidencias)
  • Sistema de incidencias posventa con ciclo de vida completo (apertura → resolución → cierre)
  • Dashboard con KPIs en tiempo real y reportes analíticos configurables por período
  • Integración CSV para importar/exportar catálogo, stock y pedidos
  • Autenticación segura con JWT y control de acceso por rol (RBAC, 4 roles)
  • Documentación completa: README técnico, Swagger API y esta memoria del proyecto

10.2 Valoración técnica

Aciertos tecnológicos

  • La arquitectura modular de NestJS mantuvo el backend organizado y escalable
  • Prisma ORM aceleró el desarrollo con tipado automático de consultas
  • TanStack Query eliminó el boilerplate de gestión de estado del servidor
  • Turborepo permitió desarrollar frontend y backend en paralelo con excelente DX

Áreas de mejora

  • Implementar tests automatizados (unitarios e integración)
  • Añadir refresh proactivo del token antes de que expire
  • Mejorar la gestión de errores con mensajes más descriptivos
  • Añadir paginación infinita al catálogo para mejor UX en móvil
